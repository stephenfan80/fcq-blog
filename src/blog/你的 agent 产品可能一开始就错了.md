过去一年我看了大量 agent 产品，也亲手在做一个买车 agent。

我越来越确信一件事：**目前绝大多数 agent 产品，都在错的赛道上**。

它们都长一个样——一个聊天输入框，一个发送按钮，几个预设 prompt 卡片，等用户写一句话，然后 AI 给一段回复。哪怕后端跑了多 agent 编排、RAG、Tool Use，前端还是那个对话框。

这个形态不是 agent 的终点，是 agent 的**原罪**。

这篇想说清楚三件事：为什么对话框是错的、真正的新范式是什么、以及以买车 agent 为例，具体应该怎么做。

---

## 一、对话框是错的，因为它假设用户知道自己要什么

Jakob Nielsen 最近在《Expressing Intent in Discovery》里提出一个概念叫**表达壁垒**：意图式 AI 要求用户用自然语言说清楚自己要什么，但大部分用户**根本写不出那句话**。

这不是用户的问题，是产品设计的问题。

更准确地说，对话框式 agent 有一个隐含假设：**用户在打开产品之前，已经知道自己想要什么，只需要把它翻译成一段文字**。

这个假设在大部分真实场景里是错的。

拿买车举个例子。一个第一次买车的用户，打开你的 agent，你让他在输入框里写清楚自己要什么——他能写出什么？"我想买个性价比高的 SUV"。

这句话对 agent 来说约等于空气。什么叫性价比高？预算多少？是家用还是通勤？他自己都没想清楚。

真实情况是什么？真实情况是这个用户**在不断刷小红书、看 B 站测评、听播客、刷朋友圈的过程中，才一点一点意识到：哦，原来我想要大空间；哦，原来我不在乎零百加速；哦，原来我不能接受两厢车**。

**意图不是预先存在的，是在探索中发现的。**

这就是 Nielsen 文章标题里"Discovery"那个词的含义。可一个对话框怎么可能支持探索？它只支持"把已知写出来"，不支持"在未知里发现"。

这是对话框式 agent 的第一个死结。

---

## 二、真正的范式转移：用户从"操作者"变成了"监督者"

Nielsen 说 AI 是 60 年来 UX 的第三次范式转移，上一次是批处理到命令行。

这句话我第一次读的时候没当回事。读了第三遍才意识到他说的是什么——**AI 改变的不是界面，是用户在系统里扮演的角色**。

过去的 UX 设计，无论是命令行还是 GUI，底层逻辑都是一样的：

> 人在脑内形成计划，然后通过控件执行这个计划。

GUI 只是比命令行更直观地呈现了那个计划——图标代替命令、拖拽代替参数、点击代替回车。人仍然是那个"做工作"的人。

意图式 AI 把这个结构打碎了。人不再做计划，人把计划外包给系统。**系统负责解释目标、选择子目标、安排动作、获取权限、处理异常**。人留下的工作是什么？是**监督**。

从"操作者"变成"监督者"，听起来是个小变化。但它改变了几件非常根本的事：

- **决策发生的位置**变了：从用户大脑，转移到系统大脑。
- **认知负担**变了：从"怎么做"转移到"评估做得对不对"。
- **错误的定义**变了：以前是用户点错了，现在是系统理解错了。

这三件事，任何一件单独拎出来，都是产品设计的大地震。

---

## 三、旧范式 vs 新范式

把这种转变翻译成产品设计语言，我做了一张表：

| 维度 | 旧范式（命令式 / GUI） | 新范式（意图式 / Agent） |
|------|----------------------|-------------------------|
| 用户角色 | 操作者 | 监督者 |
| 交互主体 | "点击路径" | "意图 + 约束 + 边界" |
| 核心输入 | 明确指令 | 模糊意图 + 上下文 |
| 设计目标 | 减少点击 | 降低意图表达成本 |
| 成功指标 | 任务完成时间 | 纠错时间、可评估性、信任校准 |
| 失败模式 | 用户点错、系统报错 | 系统误解意图、用户不敢信任 |
| 界面主元素 | 按钮、表单、菜单 | 意图镜像、过程可见、回滚入口 |
| 摩擦设计 | 越少越好 | 高风险场景主动加摩擦 |
| 反馈形式 | 即时响应 | 过程透明 + 反事实解释 |
| 护城河 | 信息密度、流程效率 | 意图捕捉精度、执行安全性 |

这张表不是我写出来装 B 的。它是一个非常实用的检查单：**你正在设计的这个功能，你默认的是哪一列？**

大部分 agent 产品的问题在于：前端沿用旧范式，后端塞新能力。两边脱节。

---

## 四、新范式的 9 个关键点

从 Nielsen 文章和我自己看的一堆 agent 实践里，我提炼出 9 个新范式的关键设计点。做 agent 产品的 PM，这 9 个点是最低标准：

**1. 意图有三部分：想要的结果、可接受的约束、委托的边界。**
不是"让用户说清楚要什么"，是"让用户说清楚这三件事"。只问第一个的产品，都在裸奔。

**2. 控制权的位置在转移。**
用户从"做工作"变成"监督工作"，这不是口号，是产品上每一个交互点都要重新想。

**3. 系统必须展示三件事：它认为你想做什么、它正在做什么、它接下来打算做什么。**
这是监督者能正常工作的最低信息需求。缺一样，用户就开始不信任。

**4. 可中断、可纠正、可回滚。**
这是新范式的安全三件套。agent 不能只有"运行 / 完成"两种状态，中间必须有干预入口。

**5. 纠错时间（time-to-correct）比任务完成时间更重要。**
任务完成时间从 3 小时压到 30 秒，但纠错时间是 30 分钟，整体体验仍然是崩的。

**6. 界面必须为"可评估性"优化。**
用户能不能一眼看出 agent 给的东西好不好？好的产品让用户 5 秒内做判断，差的产品让用户反复对比。

**7. 展示"为什么选 A 不选 B"比置信度分数有用得多。**
反事实解释教会用户系统的决策逻辑，让他知道在哪里干预才有影响。"87% 置信度"是假装自信。

**8. 满意度绑定在"感知到的能动性"上。**
用户要觉得自己在掌控系统，哪怕实际上 agent 在自动执行。掌控感缺失，agent 再强都没用。

**9. 高风险任务必须主动加摩擦。**
这一条最反直觉。过去二十年产品都在做减少步骤，到了 agent 时代，关键动作必须加确认、加分阶段授权。零摩擦意味着高风险场景下系统替你背锅。

## 五、以买车 agent 为例：这些原则怎么落到产品里

光说原则没用。下面把上面 9 条落到一个具体的产品架构里，这是我自己做买车 agent 的设计路径。

落地的底层骨架只有一句话：**不是做一个更好的 App，是把产品从"流程"重建为"持续状态空间"**。

### 1. 三栏骨架：Intent / Plan + Execution / Receipts

agent 产品不是一个漏斗，它更像游乐园——用户可以随时进、随时出、随时在几个子空间之间切换，但整张"游乐园地图"永远可见。

这个"地图"就是三栏结构：

| 栏 | 类比 | 作用 |
|----|------|-----|
| **Intent 区（左）** | 地图 / 镜子 | agent 当前对用户的理解：意图、约束、委托边界 |
| **Plan + Execution（中）** | 当前位置 / 工作台 | agent 正在做什么、接下来做什么 |
| **Receipts（右）** | 票根 / 后悔药 | 走过的痕迹、数据溯源、动作溯源、回滚入口 |

**三栏必须永远同时可见**。任何让用户"进入二级页面丢失三栏"的设计，本质都是把游乐园改回了长走廊。这是 agent 产品和传统 App 第一层的结构性区别。

### 2. Intent 区是镜子，不是商店

Intent 区最容易犯的错，是往里塞传统 App 的品牌列表、车系详情页、分类入口。

**这是根本性的走回头路**。Intent 区是 agent 理解用户的镜子——它的"用户"是 agent，解决的问题是"agent 有没有听懂我"。往镜子里塞货架，等于在监督位上塞了一个操作台，用户本能就切回"我自己来挑"的操作者心态。

Intent 区应该极简：

```
预算 15-18 万
家用 3 人
上海
保值优先
———
🔐 委托：L1（推荐+对比）
🎚️ 摩擦：标准
———
—— agent 推断 ——
动力偏好：增程 > 插混（你过去 5 次只看增程）
空间权重：高（后备箱页停留 40s×3 次）
[确认] [不对，改一下]
[编辑 Intent]
```

最核心的是最后这两行"agent 推断"。它是监督式交互的灵魂——**把 agent 偷偷推断的东西摊开在桌面上，让用户一眼看出对或不对**。没有这两行，agent 就是在黑箱里跑。

品牌列表、车系百科这些信息不是不要，是放到**"手动模式"的跳出路径里**——用户想自己翻就翻，但不占主路径。主路径永远是 agent 主导、用户监督。

### 3. 屏幕上下文是最高权重输入，输入框应该被隐藏

Nielsen 强调多模态，我在买车场景下排了优先级：

1. **屏幕上下文**——用户看什么、停多久、对比什么、快退什么，这是信号密度最高的输入
2. **语音**——路上、店里、家里，手不方便打字时用
3. **图片 / 摄像头**——在 4S 店拍一张"这个怎么样"
4. **文字**——认知负担最高，放在最后

但排完优先级只是第一步。真正的落地是一个反共识推论：**主界面不应该常驻输入框**。

常驻输入框会发出一个错误信号："请用文字告诉我你想要什么"，这把用户推回对话式范式。正确做法是：

- 默认不显示输入框
- agent 需要追问时以卡片形式临时弹出
- 用户主动想问时一个快捷键/浮动按钮调出
- 输入框永远是**最后一个入口**，不是第一个

当用户发现自己 30 分钟没打过一个字、但 agent 越来越懂他时，他才会真正意识到：**原来真的不用打字**。

屏幕上下文要真正可用，背后是一套完整的子系统——原始事件采集 → 信号语义加工 → 持久化上下文图谱 → 主动对齐 → 驱动 agent 行为。做不到位，产品就会本能地退回"请用文字告诉我要什么"，整个意图捕捉能力坍塌到对话式水平。

**信号每积累 5-10 条，agent 要主动对齐一次**。太勤烦人，太稀越推越偏。对齐的时刻也是信号从"隐式"升级为"显式"的时刻——用户点一下确认，信号权重立刻从 0.6 提到 1.0。

### 4. 渐进式委托：贯穿三栏的"信任刻度"

渐进式委托不是一个独立模块，是一根贯穿三栏的信任刻度。

**Intent 区**：常驻显示当前委托等级。这是意图三要素里的"委托边界"，必须可见、可调。

**Plan + Execution（中栏）**：除了当前正在执行的动作，还要**灰色显示锁着的后续动作**——

```
◉ 筛选候选池       ✓
◉ 抓参数（并行）   ⏳
◉ 生成方案 A/B/C   ○
─── 需要升级委托 ───
🔒 向 3 家 4S 店询价     [解锁 L2]
🔒 代约试驾             [解锁 L3]
🔒 下订金              [永不委托]
```

让更高级动作**被看见**。用户知道 agent 有更多能力，升级才会自然发生。"永不委托"也要显式标出——**承诺不做什么，比承诺做什么更重要**。

**Receipts 区**：每条执行记录打上授权标签——"询价 4S 店 L2 · 14:23"。这样用户能追溯每个动作是在什么授权下做的，责任边界清晰。

升级的最好时机是"用户正好需要这件事被做"的瞬间，不是设置页里一个冷冰冰的开关。agent 在用户成功监督 3-5 次当前级别动作后，再在**恰好需要下一级动作**的场景里冒一行提示——用证据和场景去触发，不用唠叨。

降级路径必须和升级一样顺滑。点一下就能降回 L1，不要藏。新范式的信任不是一次性交付，是**随时可撤回**的。

### 5. 分级摩擦：5 级体系 + 仪式化确认

"该摩擦的地方摩擦"不是一个开关，是一个分级体系：

| 级别 | 含义 | 示例 | UI 节奏 |
|------|------|------|---------|
| **L0 静默** | 0 摩擦 | 刷新候选池、查参数 | 流式完成，<500ms |
| **L1 回执** | 做完通知 | 生成方案 A/B/C | 右栏出一条记录 |
| **L2 软预告** | 做前 1.5s 提示 | 代发消息给 4S 店 | 顶部横幅可撤回 |
| **L3 显式确认** | 停下来等点 | 预约试驾 | 中栏冻结成确认卡片 |
| **L4 仪式化确认** | 多步 + 冷静期 + 金额复述 | 下订金 | 全流程慢接管 |
| **L5 不委托** | agent 永不做 | 签合同、过户 | 灰色标注"请亲自做" |

**L0/L1 越丝滑越好，L3/L4 故意慢**。视觉节奏和风险等级必须成正比——L0 灰底淡入无声，L4 黄/红警示色全屏接管。用户看几次 L4 就形成条件反射，这种反射比任何确认按钮都好用。

L4 尤其关键。下订金的仪式化确认我设计成三步：

- **第一步预览**：关键信息大字呈现，"车型 · 22.3 万 · 浦东店 · 订金 3000 元"，用户必须点"我看完了"
- **第二步金额复述**：要求用户**打字输入 3000 元**——不是点确认按钮。点按钮是肌肉记忆，打字强制大脑参与
- **第三步慢动效执行**：按钮改为"3 秒后付款"并倒计时，3 秒内可取消

整个流程多花 15 秒。**30 万的决策多 15 秒的摩擦，不是体验差，是设计负责**。

Receipts 区要配套一个**冷静期倒计时**：

```
● 下订金 3000 元    L4 · ⏱ 23:49 冷静期
  ↳ [申请无理由退订]
  ↳ 冷静期内 agent 可以帮你发起
```

用户敢不敢委托 L3/L4，**不是因为 agent 足够准，是因为知道出错有反悔路径**。Receipts 不只是数据溯源，也是后悔的地图。

### 6. 回执要极简：不是作文，是可点的摘要

agent 完成一件事的回执，要总结，不要复述。

一个失败的回执：

> 我已经帮您查询了理想 L7 的所有版本，共 5 款车型，分别是 Pro、Max、Max Ultra……价格从 31.98 万到 37.98 万不等……

一个好的回执：

> 找到 3 款符合你要求的车，差别在这里：[卡片 A][卡片 B][卡片 C]。
> 我已假设你要增程版本、六座优先。[修改假设]

**改了什么、触及哪些系统、用了哪些假设、哪些可以撤销**——四件事，短句，可点。用户不是来读 agent 作文的，是来做决策的。

### 7. 产品姿态：游乐园不是漏斗

最后是一件比前六点都根本的事：**整个产品的姿态，要从"流程"换成"游乐园"**。

- **首屏不再是"精选车型 feed"**：第一次进是 Intent 冷启动问卷，第二次起**直接恢复上次的三栏状态**——左栏是你的 intent，中栏是 agent 上次执行到哪里，右栏是至今所有痕迹。永远不会有"首页"，首页就是你上次的上下文。

- **所有"功能"都是 intent 的衍生**：不做独立的"车贷计算器""保险页"。用户在 Intent 区加一行"预算含贷款"，中栏的方案自动多出月供估算，右栏多一条贷款方案溯源。**"功能"作为独立导航单位消失了，它们融化成了意图的响应。**

- **没有"下一步"按钮**：用户在任何时刻能做的事只有四件——改 Intent、升降委托、看 Receipts、对中栏任何一步追问"为什么这样选"。这四件事**无序、随时可发生、不打断 agent 当前工作**。这就是游乐园——任何时刻都可以换项目。

- **"退出"是暂停，不是流失**：用户关闭 app，agent 把当前 context 打包存住。下次进来不是"欢迎回来"的空白招呼，是：

  > 你上次在对比这 3 辆车。我**刚刚**帮你刷新了最新让利报价，其中理想 L7 这个月多了 2% 优惠。要接着看吗？

  关键词是"刚刚"——用户不在的时候 agent 还在帮他干活。这是游乐园里工作人员帮你占着座位的感觉。

- **指标要换**：用漏斗转化率衡量 agent 产品会把产品带向错误的方向。DAU 要换成 DAC（Daily Active Contexts），转化率要换成 Intent-to-Action Fidelity，留存要换成 Context 完整度曲线。传统指标用错，团队就会不自觉地往产品里加 CTA、弹窗、临期优惠——一步步把游乐园改回漏斗。

这最后一条最难做。它不是 UI 改造，是**整个产品栈（信息架构、数据模型、导航逻辑、指标体系、运营节奏）围绕"上下文 + 游乐园"重组**。

做到这一步，才是"真正的 agent 产品"；做不到，三栏只是一个 UI 点缀，骨子里还是 App。

---

## 六、结尾：agent 的护城河不在模型，在意图表达成本

最后说一句最反共识的话。

大部分 agent 创业公司把护城河押在**模型**上：我用的 Claude 更强、我 RAG 做得更细、我 tool use 更稳。

我觉得都押错了。

在一个基础模型每 6 个月翻一代的行业里，模型不是护城河，**把意图表达成本降到接近零的产品能力才是**。

这个能力具体是什么？是：

- 用多模态、上下文、隐式推断，把用户脑子里那团模糊的东西转译成结构化意图的能力
- 用可见用户模型、主动对齐，让用户在监督中逐步校准 agent 的能力
- 用渐进式委托、分层摩擦，让用户在安全的前提下逐步放权的能力
- 用反事实解释、过程透明，让用户真正看懂 agent 决策的能力

这些东西加起来，才是真正的 agent 产品。

对话框只是最简陋的那一层意图采集器。以它为中心做产品，就像以键盘为中心做 GUI 一样——方向从一开始就错了。

做 agent 产品的 PM，如果你的路线图上第一件事不是"怎么降低用户的意图表达成本"，你大概率在错的赛道上奔跑。
