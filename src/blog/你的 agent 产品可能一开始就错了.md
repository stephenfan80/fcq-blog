过去一年我看了大量 agent 产品，也亲手在做一个买车 agent。

我越来越确信一件事：**目前绝大多数 agent 产品，都在错的赛道上**。

它们都长一个样——一个聊天输入框，一个发送按钮，几个预设 prompt 卡片，等用户写一句话，然后 AI 给一段回复。哪怕后端跑了多 agent 编排、RAG、Tool Use，前端还是那个对话框。

这个形态不是 agent 的终点，是 agent 的**原罪**。

这篇想说清楚三件事：为什么对话框是错的、真正的新范式是什么、以及以买车 agent 为例，具体应该怎么做。

---

## 一、对话框是错的，因为它假设用户知道自己要什么

Jakob Nielsen 最近在《Expressing Intent in Discovery》里提出一个概念叫**表达壁垒**：意图式 AI 要求用户用自然语言说清楚自己要什么，但大部分用户**根本写不出那句话**。

这不是用户的问题，是产品设计的问题。

更准确地说，对话框式 agent 有一个隐含假设：**用户在打开产品之前，已经知道自己想要什么，只需要把它翻译成一段文字**。

这个假设在大部分真实场景里是错的。

拿买车举个例子。一个第一次买车的用户，打开你的 agent，你让他在输入框里写清楚自己要什么——他能写出什么？"我想买个性价比高的 SUV"。

这句话对 agent 来说约等于空气。什么叫性价比高？预算多少？是家用还是通勤？他自己都没想清楚。

真实情况是什么？真实情况是这个用户**在不断刷小红书、看 B 站测评、听播客、刷朋友圈的过程中，才一点一点意识到：哦，原来我想要大空间；哦，原来我不在乎零百加速；哦，原来我不能接受两厢车**。

**意图不是预先存在的，是在探索中发现的。**

这就是 Nielsen 文章标题里"Discovery"那个词的含义。可一个对话框怎么可能支持探索？它只支持"把已知写出来"，不支持"在未知里发现"。

这是对话框式 agent 的第一个死结。

## 二、真正的范式转移：用户从"操作者"变成了"监督者"

Nielsen 说 AI 是 60 年来 UX 的第三次范式转移，上一次是批处理到命令行。

这句话我第一次读的时候没当回事。读了第三遍才意识到他说的是什么——**AI 改变的不是界面，是用户在系统里扮演的角色**。

过去的 UX 设计，无论是命令行还是 GUI，底层逻辑都是一样的：

> 人在脑内形成计划，然后通过控件执行这个计划。

GUI 只是比命令行更直观地呈现了那个计划——图标代替命令、拖拽代替参数、点击代替回车。人仍然是那个"做工作"的人。

意图式 AI 把这个结构打碎了。人不再做计划，人把计划外包给系统。**系统负责解释目标、选择子目标、安排动作、获取权限、处理异常**。人留下的工作是什么？是**监督**。

从"操作者"变成"监督者"，听起来是个小变化。但它改变了几件非常根本的事：

- **决策发生的位置**变了：从用户大脑，转移到系统大脑。
- **认知负担**变了：从"怎么做"转移到"评估做得对不对"。
- **错误的定义**变了：以前是用户点错了，现在是系统理解错了。

这三件事，任何一件单独拎出来，都是产品设计的大地震。

---

## 三、旧范式 vs 新范式

把这种转变翻译成产品设计语言，我做了一张表：

| 维度 | 旧范式（命令式 / GUI） | 新范式（意图式 / Agent） |
|------|----------------------|-------------------------|
| 用户角色 | 操作者 | 监督者 |
| 交互主体 | "点击路径" | "意图 + 约束 + 边界" |
| 核心输入 | 明确指令 | 模糊意图 + 上下文 |
| 设计目标 | 减少点击 | 降低意图表达成本 |
| 成功指标 | 任务完成时间 | 纠错时间、可评估性、信任校准 |
| 失败模式 | 用户点错、系统报错 | 系统误解意图、用户不敢信任 |
| 界面主元素 | 按钮、表单、菜单 | 意图镜像、过程可见、回滚入口 |
| 摩擦设计 | 越少越好 | 高风险场景主动加摩擦 |
| 反馈形式 | 即时响应 | 过程透明 + 反事实解释 |
| 护城河 | 信息密度、流程效率 | 意图捕捉精度、执行安全性 |

这张表不是我写出来装 B 的。它是一个非常实用的检查单：**你正在设计的这个功能，你默认的是哪一列？**

大部分 agent 产品的问题在于：前端沿用旧范式，后端塞新能力。两边脱节。

## 四、新范式的 9 个关键点

从 Nielsen 文章和我自己看的一堆 agent 实践里，我提炼出 9 个新范式的关键设计点。做 agent 产品的 PM，这 9 个点是最低标准：

**1. 意图有三部分：想要的结果、可接受的约束、委托的边界。**
不是"让用户说清楚要什么"，是"让用户说清楚这三件事"。只问第一个的产品，都在裸奔。

**2. 控制权的位置在转移。**
用户从"做工作"变成"监督工作"，这不是口号，是产品上每一个交互点都要重新想。

**3. 系统必须展示三件事：它认为你想做什么、它正在做什么、它接下来打算做什么。**
这是监督者能正常工作的最低信息需求。缺一样，用户就开始不信任。

**4. 可中断、可纠正、可回滚。**
这是新范式的安全三件套。agent 不能只有"运行 / 完成"两种状态，中间必须有干预入口。

**5. 纠错时间（time-to-correct）比任务完成时间更重要。**
任务完成时间从 3 小时压到 30 秒，但纠错时间是 30 分钟，整体体验仍然是崩的。

**6. 界面必须为"可评估性"优化。**
用户能不能一眼看出 agent 给的东西好不好？好的产品让用户 5 秒内做判断，差的产品让用户反复对比。

**7. 展示"为什么选 A 不选 B"比置信度分数有用得多。**
反事实解释教会用户系统的决策逻辑，让他知道在哪里干预才有影响。"87% 置信度"是假装自信。

**8. 满意度绑定在"感知到的能动性"上。**
用户要觉得自己在掌控系统，哪怕实际上 agent 在自动执行。掌控感缺失，agent 再强都没用。

**9. 高风险任务必须主动加摩擦。**
这一条最反直觉。过去二十年产品都在做减少步骤，到了 agent 时代，关键动作必须加确认、加分阶段授权。零摩擦意味着高风险场景下系统替你背锅。

## 五、以买车 agent 为例：这些原则怎么落到产品里

光说原则没用，要落到具体设计里。我用自己在做的买车 agent 来走一遍。

### 1. 意图捕捉不是写 prompt，是结构化对话

普通用户打开买车 agent，不会写出"预算 30 万以内、家用 SUV、7 座优先、不在乎加速"这种完整 prompt。

那我就不让他写。

我让 agent 主导一个**结构化但有弹性的对话**：agent 问几个核心问题——几口人用、主要用在哪、预算大概区间、介意的点是什么——用户可以用语音、短句、甚至从若干选项里选。agent 后台把这些答案翻译成一个**结构化意图对象**：结果 + 约束 + 委托边界。

关键是这个意图对象**对用户可见、可编辑**。它不是黑箱，不是 agent 自己推断完就藏起来。用户随时能打开看：哦，agent 以为我预算是 30 万以内、以为我一定要 7 座——不对，我 5 座可以接受，改一下。

这是 Nielsen 说的"可见、可编辑的用户模型"。没有这个东西的 agent，约等于在黑箱里跑。

### 2. 隐式意图推断，然后立即对齐

用户在 agent 里刷车的时候，每一次点击、停留、对比，都是信号。

- 他连续看了三辆插混 SUV ，说明他对动力形式已经有偏好。
- 他把"理想 L7"和"问界 M7"放到对比栏，说明"增程 + 家用六座"是他实际关心的维度。
- 他在某个车的后备箱尺寸页面停了 40 秒，说明空间是真实决策因子。

agent 后台要实时在推这个隐式意图。但**推断完不能偷偷用**，要定期主动对齐：

> "我观察到你最近只看增程六座 SUV，我把推荐池缩到这个范围内了。不对请告诉我。"

这个"主动对齐"是监督式交互的灵魂。隐式推断 + 不对齐 = 越推越偏。隐式推断 + 对齐 = 越推越准。

### 3. 渐进式委托

买车 agent 能做很多事——比价、约试驾、谈折扣、甚至下订金。但**不是所有事都能在第一天就委托给 agent**。

渐进式委托的意思是：用户对 agent 的信任是逐步建立的，agent 的权限也应该逐步解锁。

我现在的设计是：

- **第一阶段：推荐 + 对比。** agent 帮你筛车、比参数、分析差异。你自己做决定。
- **第二阶段：代办信息流。** 你授权 agent 去和 4S 店要报价、约试驾时间。agent 只负责沟通，不签字不付款。
- **第三阶段：代办低风险动作。** 比如预订试驾、比如把心仪车发到家人微信。
- **第四阶段（可能永远不到）：代办高风险动作。** 比如下订金、比如签合同。这一步我现在觉得不该让 agent 做。

渐进式委托不是"产品功能太少的遮羞布"，是**让用户在监督中建立信任的路径**。一上来就说"我帮你全包了"的 agent，要么是骗子，要么是灾难。

### 4. 买车是高风险任务，反而不能零摩擦

这是我自己一开始想错的点。

我一开始想做一个"一句话买车"的 demo：用户说一句"帮我订那辆理想 L7"，agent 下一秒就搞定。

但冷静下来想：**买车是一次 30 万的决策，用户真的要一句话就交给 agent 吗？**

用户需要的不是"零摩擦"，是"**只在该摩擦的地方摩擦**"。

所以我现在的设计是：查信息、比参数、看评测，这些低风险动作做到极致丝滑，0 思考负担。但一旦动到**下订金、签合同、预约到店**这三个关键节点，必须要有**显式确认**：

- 展示 agent 接下来要做什么
- 展示所有参数（车型、价格、经销商、时间、金额）
- 展示可以回滚的方式
- 要用户点一次确认

这三个节点的"多一次点击"，不是用户体验差，是**把控制权交还给用户**。是新范式下产品对用户的尊重。

### 5. 多模态输入优先级

Nielsen 强调情境感知和多模态。在买车这个场景里我排了一个优先级：

1. **屏幕上下文最有用**——用户在看什么车、看哪个参数页面、对比了什么，这是最信号密度的输入。
2. **语音次之**——用户在路上、在店里、在家里，手不方便打字，语音降低表达成本。
3. **图片 / 摄像头再次之**——用户拍一张在 4S 店看到的车，"这个怎么样"，这是非常自然的提问方式。
4. **文字最后**——文字在所有模态里**认知负担最高**，最不适合做意图捕捉的主入口。

大部分对话式 agent 把文字放在第一位，这是产品逻辑的错位。

### 6. 回执要极简，别让用户读到累

agent 完成一件事之后要给回执，但 Nielsen 这篇提醒了我一件事：**回执要总结，不要复述**。

一个失败的回执长这样：

> 我已经帮您查询了理想 L7 的所有版本，共 5 款车型，分别是 Pro、Max、Max Ultra……价格从 31.98 万到 37.98 万不等……我还查询了最近一个月的用户评价，发现……

用户根本不会读。

一个好的回执长这样：

> 找到 3 款符合你要求的车，差别在这里：[卡片 A] [卡片 B] [卡片 C]。
> 我已假设你要增程版本、六座优先。[修改假设]

**改了什么、触及哪些系统、用了哪些假设、哪些可以撤销**——四件事，短句，可点。

用户不是来读 agent 作文的，是来做决策的。

## 六、结尾：agent 的护城河不在模型，在意图表达成本

最后说一句最反共识的话。

大部分 agent 创业公司把护城河押在**模型**上：我用的 Claude 更强、我 RAG 做得更细、我 tool use 更稳。

我觉得都押错了。

在一个基础模型每 6 个月翻一代的行业里，模型不是护城河，**把意图表达成本降到接近零的产品能力才是**。

这个能力具体是什么？是：

- 用多模态、上下文、隐式推断，把用户脑子里那团模糊的东西转译成结构化意图的能力
- 用可见用户模型、主动对齐，让用户在监督中逐步校准 agent 的能力
- 用渐进式委托、分层摩擦，让用户在安全的前提下逐步放权的能力
- 用反事实解释、过程透明，让用户真正看懂 agent 决策的能力

这些东西加起来，才是真正的 agent 产品。

对话框只是最简陋的那一层意图采集器。以它为中心做产品，就像以键盘为中心做 GUI 一样——方向从一开始就错了。

做 agent 产品的 PM，如果你的路线图上第一件事不是"怎么降低用户的意图表达成本"，你大概率在错的赛道上奔跑。
